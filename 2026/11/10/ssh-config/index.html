SSH 配置: 跳板机自动输入密码, 反向代理复用

我在 Mac 上用终端, VS Code 和 Codex 等连同一台 GPU 服务器. 跳板机只接受密码, 目标机用 SSH 密钥.

本来用的 SSH 复用加反向代理很舒服, Codex 突然来个强制不使用复用 SSH, 很难受. 于是倒腾下面这些东西.

跳板机用 sshpass 配置自动输入密码

~/.ssh/config 如下. ProxyCommand 写在一行.

Host gpu
    HostName 127.0.0.1
    Port 2201
    User dev
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
    ProxyCommand /opt/homebrew/bin/sshpass -p 'REPLACE_WITH_PASSWORD' /usr/bin/ssh -p 2222 -l jump -o PreferredAuthentications=password -W "%h:%p" -- gateway.example.com

执行 ssh gpu 时, sshpass 给内层 SSH 输入跳板密码. 登录跳板后, -W "%h:%p" 让跳板连接它那边的 127.0.0.1:2201, 外层 SSH 再用密钥登录目标机.

-p 会把明文密码留在配置里, 也可能在进程参数中短暂暴露, 见仁见智.

独立的反向代理 SSH 连接

Codex 在 SSH 连接时会禁用 ControlMaster. 把 RemoteForward 写进 Host gpu, 终端和 Codex 就会分别申请同一个远端监听端口, 后来的连接会遇到端口冲突.

我把转发放到单独的 SSH 连接里. 每次登录成功后, LocalCommand 把当前 SSH 的 PID 登记到后台. 后台按主机别名管理隧道, 用 macOS 的 kqueue 监听进程退出. 第一条连接触发隧道, 最后一条登记过的连接退出后释放端口.

把 完整脚本 保存到 ~/.ssh/ssh-reverse-proxy.py, 再把这两行加进 Host gpu.

PermitLocalCommand yes
LocalCommand exec /usr/bin/python3 "$HOME/.ssh/ssh-reverse-proxy.py" "%n" "127.0.0.1:7898:127.0.0.1:7897"

后台实际跑的是这条命令.

/usr/bin/ssh -nNT -S none \
    -o BatchMode=yes \
    -o PermitLocalCommand=no \
    -o ExitOnForwardFailure=yes \
    -R 127.0.0.1:7898:127.0.0.1:7897 gpu

-S none 禁用连接复用, PermitLocalCommand=no 防止隧道再次触发登记. 远端的 127.0.0.1:7898 转发到 Mac 上的 HTTP 代理 127.0.0.1:7897. 绑定失败时, 只有专用隧道退出, 登录连接可以继续用.

在远端按需给命令加代理.

https_proxy=http://127.0.0.1:7898 curl -I https://example.org

也可以直接写进 zsh 配置.
