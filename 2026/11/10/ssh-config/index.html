我的 SSH 配置：跳板免输密码，反向代理只开一条

我在 Mac 上经常从终端和 Codex 连同一台 GPU 服务器。跳板只接受密码，目标机可以用密钥。目标机装依赖时还要借用 Mac 上的代理，所以两边都连着的时候，远端应该只有一个代理端口，关掉其中一边也还能用。

下面用 gpu 和 gpu-gateway 作示例。地址、账号和 SSH 端口都换过。

跳板密码交给钥匙串

我需要省掉的是跳板的密码提示。在 macOS 上，可以让 OpenSSH 通过 SSH_ASKPASS 从钥匙串读密码。目标机仍然用自己的 SSH 密钥。

先存一次密码。最后的 -w 留空，security 会提示输入，密码不会出现在命令行里。

security add-generic-password -a jump -s ssh:gpu-gateway -w

把下面的脚本存为 ~/.ssh/gpu-gateway-askpass，再执行 chmod 700 ~/.ssh/gpu-gateway-askpass。如果换了跳板账号或地址，也把脚本里的提示文字换掉。

#!/bin/sh
case "${1-}" in
    "jump@gateway.example.com's password: ")
        exec /usr/bin/security find-generic-password -a jump -s ssh:gpu-gateway -w
        ;;
    *)
        exit 1
        ;;
esac

~/.ssh/config 里分开写两跳。每条 ProxyCommand 在配置里占一整行。

Host gpu
    HostName 127.0.0.1
    Port 2201
    User dev
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
    ProxyCommand SSH_ASKPASS="$HOME/.ssh/gpu-gateway-askpass" SSH_ASKPASS_REQUIRE=force /usr/bin/ssh -W "%h:%p" gpu-gateway

Host gpu-gateway
    HostName gateway.example.com
    Port 2222
    User jump
    PreferredAuthentications password
    BatchMode no
    NumberOfPasswordPrompts 1
    StrictHostKeyChecking yes

ssh gpu 会先启动一条到 gpu-gateway 的 SSH。只有这条连接设置了 SSH_ASKPASS，遇到跳板密码提示时才会取钥匙串里的密码。登录跳板后，-W 让跳板去连它那边的 127.0.0.1:2201，外层 SSH 再用密钥登录目标机。首次使用前要核对两台机器的主机密钥指纹，把它们存入 known_hosts。OpenSSH 的 SSH_ASKPASS 说明 · Apple 的 security 手册

登录各走各的，反向代理共用一条

Mac 上的 HTTP 代理听在 127.0.0.1:7897。SSH 在远端开 127.0.0.1:7898，把连到这个端口的流量送回 Mac。远端临时需要代理时，我给那条命令加个环境变量。

https_proxy=http://127.0.0.1:7898 curl -I https://example.org

这里的端口只能有一条连接负责监听。所有客户端都复用同一个 ControlMaster 时，可以直接在主连接上配 RemoteForward。我这边 Codex 会另起独立的 SSH 连接。把 RemoteForward 配到登录别名上，两条连接就会各自申请同一个远端端口，后来的那条会撞上已经占用的监听。

我的配置里，登录连接只负责登记。第一条登录成功后，后台起一条专用的 SSH 隧道。终端和 Codex 可以各开各的连接，最后一条登记过的连接退出，后台才收掉隧道。

客户端需要用本机 OpenSSH 读取这份配置，并允许执行 LocalCommand。把脚本存到 ~/.ssh/ssh-reverse-proxy.py，再把这两行加到上面的 Host gpu 里，放在 Host gpu-gateway 之前。

PermitLocalCommand yes
LocalCommand exec /usr/bin/python3 "$HOME/.ssh/ssh-reverse-proxy.py" "%n" "127.0.0.1:7898:127.0.0.1:7897"

LocalCommand 在 SSH 登录成功后执行。用 exec 让 Python 直接接替中间的 shell，脚本就能用 os.getppid() 拿到调用它的 SSH 进程。它按 %n（这里是固定别名 gpu）登记，用 Unix 套接字收登记，用 macOS 的 kqueue 等进程退出。登记和关隧道用同一把锁，关之前先处理排队中的新登记。

后台真正跑的命令是这条。

ssh -nNT -S none \
    -o BatchMode=yes \
    -o PermitLocalCommand=no \
    -o ExitOnForwardFailure=yes \
    -R 127.0.0.1:7898:127.0.0.1:7897 gpu

-S none 让隧道用独立连接，PermitLocalCommand=no 防止它也来登记。目标机这跳用 BatchMode=yes，需要输口令的私钥要先载入 ssh-agent。跳板那一跳由 ProxyCommand 单独取密码。端口绑定失败时，退出的只有这条隧道，登录还能用。脚本确认的是登记成功，刚登录时代理可能还在建立。OpenSSH 的 -R 和 -S 说明 · LocalCommand 和 RemoteForward 说明
